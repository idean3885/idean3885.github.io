# ADR-0005: 부하 대응을 글 전체의 관통 주제로 둔다

## Status

Accepted (2026-08-27)

## Context

기술 단위로 글을 써 왔다. gRPC 실측, 가상 스레드, 커넥션 상한이 각각 독립 글로 있고 서로를 참조하지 않는다.

두 가지가 걸렸다.

**각 글이 왜 그 기술을 봤는지 답하지 않는다.** gRPC 실측은 면접 대비로 시작했으나 글에 그 동기가 없다. 남는 명분이 「궁금해서 측정했다」 수준이라 1회성으로 휘발된다. 과거 글이 장황했던 원인도 같다. 무엇을 말하려는 글인지가 착수 시점에 정해지지 않았다.

**이력서·포트폴리오에서 트래픽 경험이 부족한 영역으로 남아 있다.** 채용 쪽이 트래픽 경험을 묻는 이유는 규모 자체가 아니라 부하가 왔을 때 어디가 먼저 막히고 무엇으로 막았는지다. 그 답으로 나오는 것이 gRPC·서킷 브레이커 같은 기술이다. 기술은 해결 방안이고 질문이 아니다.

기술을 단위로 나누면 이 질문이 어디에도 없다. 글마다 기술 설명이 반복되고 판단 근거는 흩어진다.

## Decision

1. **관통 주제를 한 문장으로 고정한다.** 「부하가 왔을 때 무엇이 먼저 막히는가, 그리고 그 지점마다 어떤 선택이 있는가」
2. **글은 기술이 아니라 막히는 지점으로 정렬한다.** 새 글 착수 시 어느 지점을 다루는지 먼저 정한다.
3. **시리즈로 묶지 않는다.** ADR-0003 을 그대로 유지하고 번호 없는 독립 글로 둔다. 각 글 도입부 한 문장으로 관통 주제를 참조한다.
4. **경력 사례와 개인 실측을 같은 주제에 두되 이력서 칸은 분리한다.** 요건 근거는 경력(미터링 파이프라인), 개인 실측은 개인 프로젝트 절이다. 노트북 단일 호스트 실측을 요건 충족 근거로 계산하지 않는다.
5. **기존 글을 소급 개편하지 않는다.** 미터링 글은 작성 시점이 이르고 품질 기준이 지금과 달라 그대로 둔다. 관통 주제에 붙는 장으로 기록만 한다.
6. **외부 플랫폼 글도 이 주제를 따른다.** 유입을 위해 벨로그 같은 다른 플랫폼에 쓰는 글도 같은 지점 구성에서 한 장을 맡는다. 원문은 블로그에 두고 같은 내용을 양쪽에 복제하지 않는다.

장 구성은 다음과 같다.

| 막히는 지점 | 글 | 성격 |
|---|---|---|
| 커넥션 | 요청률 고정으로 부하를 걸어 커넥션 상한을 찾은 기록 | 개인 실측, 미작성 |
| 프로토콜 | MSA 는 왜 gRPC 를 쓰는가 | 개인 실측, 발행됨 |
| 스레드 모델 | 가상 스레드와 지연 분포 | 개인 실측, 벨로그 발행됨 |
| 장애 전파 | 서킷 브레이커 | 미학습 |
| 데이터 계층 | 미터링 용량을 세 제약으로 역산한 의사결정 | **경력**, 발행됨 |

마지막 줄이 이 구성의 근거다. 개인 실측과 실제 운영 사례가 같은 질문에 답하면, 서술이 「부족한 영역을 공부했다」에서 「같은 판단을 운영에서도 했고 나머지 지점을 실측으로 채우는 중」으로 바뀐다.

## Consequences

긍정

- 새 글 착수 시 답할 질문이 관통 주제에서 나온다. 착수 게이트의 PU1 이 매번 처음부터 정해지지 않는다.
- 개인 실측이 경력 사례와 같은 문맥에 놓여 학습 기록으로 휘발되지 않는다.
- 기술 설명 반복이 줄어든다. 각 글은 자기 지점만 다루고 나머지는 링크한다.

부정

- 관통 주제에 맞지 않는 글의 자리가 애매해진다. 개발 사전 계열이 그렇다. 그 글들은 이 주제 밖으로 두고 별도 판단한다.
- 장 구성 표가 낡는다. 글이 늘면 이 ADR 을 갱신하거나 표를 CLAUDE.md 로 옮겨야 한다.
- 장이 여러 플랫폼에 흩어진다. 어느 지점이 어디에 있는지는 장 구성 표만 알고 있어, 표를 갱신하지 않으면 같은 지점을 두 번 쓰게 된다.

## Alternatives Considered

| 대안 | 기각 사유 |
|---|---|
| 기술 단위 독립 글 유지 | 왜 그 기술을 봤는지가 어디에도 없다. 명분이 휘발되는 현재 상태 |
| 시리즈로 묶어 인덱스 글 신설 | ADR-0003 이 폐지한 구조다. 미루기와 인사이트 분산이 다시 생긴다 |
| 개인 실측을 요건 근거로 함께 계산 | 단일 호스트 인메모리 측정은 트래픽을 받은 기록이 아니다. 면접에서 방어되지 않는다 |
| 미터링 글을 트래픽 대응으로 다시 씀 | 품질 기준이 지금과 달라 재작성 규모가 된다. 관통 주제 고정이 먼저다 |
