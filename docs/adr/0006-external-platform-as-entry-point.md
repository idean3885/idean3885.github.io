# ADR-0006: 외부 플랫폼은 원문의 입구를 맡는다

## Status

Accepted (2026-08-28)

## Context

ADR-0005 의 Decision 6 은 외부 플랫폼 글도 지점 구성에서 한 장을 맡고 같은 내용을 양쪽에 복제하지 않는다고 정했다. 지점의 소유권을 플랫폼끼리 나누는 구조다.

그 구조로 첫 지점인 커넥션을 어디에 쓸지 정하려니 세 갈래가 다 어색했다. 벨로그가 그 지점을 가지면 색인 자산이 외부에 쌓인다. 블로그가 가지면 외부 입구가 없다. 양쪽이 같은 회차를 다루면 중복 판정 위험이 남는다.

전제를 다시 봤다. 외부 발행을 시작한 이유는 지점 분배가 아니다. 블로그가 5개월 넘게 색인되지 않아, 이미 색인된 플랫폼에서 블로그로 들어오는 링크를 만드는 것이 목적이었다.

중복 판정도 좁게 봐야 했다. 검색엔진이 두 페이지를 같은 글로 묶는 것은 본문을 그대로 옮겼을 때다. 벨로그의 가상 스레드 글은 블로그 원문과 같은 실험 값을 다루는데 서술이 달라 그 판정을 받지 않았고 색인도 유지됐다.

## Decision

1. **원문은 블로그에 둔다.** 지점 하나가 외부 플랫폼만 갖는 경우를 두지 않는다.
2. **외부 플랫폼에는 요약을 새로 써서 원문으로 링크한다.** 본문을 옮기지 않는다.
3. **요약은 값과 표를 공유해도 서술은 새로 쓴다.** 외부 플랫폼은 대표 페이지 지정 태그를 외부 도메인으로 걸어 주지 않는다. 문장이 겹치면 색인된 쪽이 대표로 뽑히고 원문이 밀린다.
4. **장마다 외부 입구를 하나씩 둘 수 있다.** 요약은 짧아 편당 부담이 없고, 색인 회복의 지렛대가 외부 링크 개수다.
5. **지점별 현황 표를 CLAUDE.md 로 옮긴다.** ADR 은 결정을 담고 현황은 담지 않는다. ADR-0005 가 부정적 결과로 적은 「장 구성 표가 낡는다」를 여기서 해소한다.

ADR-0005 의 나머지 결정은 그대로 유지한다. Decision 6 만 이 ADR 로 대체되므로 Superseded 가 아니다. ADR-0004 가 ADR-0003 의 적용 범위를 한정할 때와 같은 관계다.

## Consequences

긍정

- 새 글마다 「어느 플랫폼이 이 지점을 갖는가」를 판단하지 않는다. 원문은 항상 블로그다.
- 장마다 입구를 붙일 수 있어 외부 링크가 누적된다. 색인 회복의 유일한 지렛대가 그것이다.
- 요약은 원문이 완성된 뒤에 쓰므로 착수 게이트에서 답할 질문이 이미 정해져 있다.

부정

- 플랫폼마다 서술을 새로 써야 해 한 지점에 두 번 쓰는 비용이 든다.
- 스레드 모델은 이 결정 전에 벨로그에서 전체 글로 발행돼 예외로 남는다. 블로그 쪽 원문은 gRPC 글 4장이 겸하고 있어 단독 글이 아니다.
- 요약이 낡는다. 원문을 고쳐도 외부 플랫폼 글은 따라오지 않는다. 값을 수정할 때는 양쪽을 함께 봐야 한다.

## Alternatives Considered

| 대안 | 기각 사유 |
|---|---|
| 벨로그가 그 지점의 원문을 갖는다 (ADR-0005 D6) | 색인 자산이 외부 플랫폼에 쌓인다. 블로그를 살리려고 시작한 일과 반대 방향이다 |
| 본문을 양쪽에 그대로 올린다 | 벨로그만 색인된 상태라 벨로그가 대표로 뽑히고 블로그 원문이 밀린다 |
| 외부 발행을 하지 않고 블로그만 쓴다 | 색인이 열리지 않는 원인이 외부 링크 부재다. 지렛대를 버리는 선택이다 |
| ADR-0005 를 제자리에서 고친다 | ADR 은 영구 기록이다. 어제 정한 문안을 지우면 왜 바뀌었는지가 남지 않는다 |
